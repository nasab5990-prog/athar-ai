# أثَر | ATHAR AI — إصدار تطوير المصادقة

## ما يتضمنه هذا الإصدار
- تصحيح بنية الشريط الجانبي لتبقى مجموعاته الأربع بدل القائمة القديمة المكررة.
- إزالة كلمات المرور التجريبية واختيار الدور يدويًا من شاشة الدخول.
- تسجيل دخول برمز OTP يرسل إلى البريد المسجل، صالح 10 دقائق، مع حد لمحاولات التحقق.
- أدوار يحددها مسؤول النظام: `teacher` المعلم، `senior_teacher` المعلم الأول، `principal` المدير، `parent` ولي الأمر.
- جلسات خادمية بملف تعريف ارتباط HttpOnly، وتحقق صلاحيات API في الخادم، وسجل تدقيق أساسي.
- قيود النطاقات الرسمية المطلوبة: `@moe.om` و`@edu.moe.om`.
- واجهة الموقع الحالية تبقى ثابتة ويمكن نشرها على Netlify، لكن API يجب تشغيله على خادم Node.js منفصل مع تخزين دائم.

## مهم جدًا
هذا الإصدار **ليس جاهزًا للنشر الإنتاجي بمجرد رفعه إلى Netlify**. Netlify يستضيف الواجهة الثابتة، أما المصادقة الآمنة وقاعدة البيانات فيجب تشغيلهما على خدمة Node.js تدعم التخزين الدائم (مثل خدمة backend على Render أو Railway أو خادم المؤسسة). لا تستخدم بيانات طلبة حقيقية قبل مراجعة الأمان وسياسة الخصوصية وتجربة الصلاحيات.

## تشغيل محلي
1. ثبّت Node.js 20 أو أحدث.
2. انسخ `.env.example` إلى `.env` واملأ القيم الحقيقية. لا ترفع `.env` إلى GitHub.
3. أنشئ القاعدة وثبّت الحزم:
   ```bash
   npm install
   ```
4. أنشئ مستخدمًا يدويًا من الطرفية (المستخدمون لا يختارون أدوارهم من شاشة الدخول):
   ```bash
   npm run create-user -- teacher1@moe.om "اسم المعلم" teacher SCHOOL-001
   npm run create-user -- senior1@edu.moe.om "المعلم الأول" senior_teacher SCHOOL-001
   npm run create-user -- principal@moe.om "مدير المدرسة" principal SCHOOL-001
   npm run create-user -- parent1@moe.om "ولي الأمر" parent SCHOOL-001 STUDENT-001
   ```
   استبدل عناوين البريد والمدرسة ومعرّف الطالب بقيم صحيحة. البريد يجب أن يكون حقيقيًا ويمكن الوصول إليه.
5. شغّل الخادم:
   ```bash
   npm start
   ```
6. اختبر `GET /api/health`. يجب أن يعيد `{"ok":true,"service":"athar-api"}`.
7. انشر الواجهة على Netlify، ثم عدّل `config.js` واجعل `apiBase` عنوان الخادم الفعلي، مثال:
   ```js
   window.ATHAR_CONFIG = { apiBase: 'https://YOUR-BACKEND-HOST' };
   ```
   اضبط `FRONTEND_ORIGIN` في الخادم على نطاق Netlify الدقيق، واستخدم HTTPS. لأن الواجهة والخادم قد يكونان على نطاقين مختلفين، اختبر إعدادات Cookies/SameSite في المتصفح؛ قد يتطلب النشر في النطاقات العابرة إعدادًا خاصًا أو استضافة API تحت نطاق فرعي تابع للموقع.

## الصلاحيات في API
- المعلم: إنشاء سجلات تربوية ضمن مدرسته، ويرى سجلاته والسجلات المشتركة.
- المعلم الأول: مراجعة سجلات المدرسة.
- المدير: قراءة سجلات المدرسة وإدارة عرض حسابات المستخدمين في المدرسة.
- ولي الأمر: قراءة سجلات `parent_view` المرتبطة بمعرّف الطالب المربوط بالحساب فقط.
- هذه سياسة أساس أولي؛ يجب تدقيق جميع نقاط API واختبار حالات منع الوصول قبل الإنتاج.

## ما يزال مطلوبًا قبل وصف النظام بأنه مكتمل
- إعداد SMTP حقيقي وإجراء اختبار استلام OTP.
- تشغيل قاعدة البيانات على تخزين دائم وأخذ نسخ احتياطية.
- ربط كل عمليات الواجهة (الطلبة، التقويم، التدخل، قياس الأثر) بـ API بدل `localStorage`؛ ما زالت بعض بيانات الواجهة الحالية محلية في هذا الإصدار.
- ربط الطالب بحساب ولي الأمر بسجل موثوق من المدرسة.
- مراجعة أمنية واختبارات فعلية لكل دور، واختبارات جوال وإمكانية وصول.
- مراجعة قانونية/مؤسسية للخصوصية وحفظ بيانات الطلبة في عُمان.

## النشر على Netlify
انشر ملفات الواجهة الثابتة فقط (`index.html`, `style.css`, `app.js`, `config.js`، وملفات الأيقونات عند توفرها). لا تنشر `server.js` على أنه backend يعمل تلقائيًا داخل موقع Netlify الثابت. لا تضع أسرار SMTP أو مفاتيح الجلسات في ملفات الواجهة أو GitHub.
