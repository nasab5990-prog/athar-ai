# أثَر | إصدار التطوير الثالث — دليل النشر والاختبار

يتضمن هذا الإصدار: تنظيف شاشة الدخول، ربط سجلات الطلبة والتقويمات والتدخلات بقيود المدرسة والحساب، فصل حساب الطالب عن ولي الأمر، إضافة إدارة حسابات المدرسة، واستبدال المؤشرات التجريبية بمؤشرات محسوبة من السجلات الفعلية.

## 1) ملفات الواجهة على GitHub Pages

استبدل الملفات التالية في جذر مستودع `athar-ai` بالملفات الموجودة في هذه الحزمة:

- `index.html`
- `app.js`
- `config.js`
- `style.css`
- `manifest.json`

واستخدم ملفي `icon-192.png` و`icon-512.png` المرفقين إذا لم تكن لديك أيقونات أحدث. تأكد أن إعداد GitHub Pages ينشر الفرع `main` من المجلد `/ (root)`.

ملف `config.js` في هذه الحزمة يشير إلى خادم Render الحالي:

`https://athar-ai-i7he.onrender.com`

## 2) ملفات الخادم على Render

استبدل في المستودع/خدمة Render الملفات التالية:

- `server.js`
- `create-user.js`
- `package.json`

ثم اجعل أمر البناء `npm install` وأمر التشغيل `node server.js`.

## 3) قاعدة البيانات الدائمة — خطوة ضرورية

قاعدة البيانات SQLite تحفظ الطلبة والحسابات والتقويمات والتدخلات. نظام الملفات في خدمة الاستضافة قد يكون مؤقتًا ما لم تضف قرصًا دائمًا.

في Render:

1. افتح خدمة `athar-ai`.
2. من قسم Disks أضف Persistent Disk إذا لم يكن موجودًا.
3. اجعل Mount Path هو `/var/data`.
4. اجعل `DB_PATH=/var/data/athar.sqlite` فقط عندما تكون قاعدة البيانات القديمة قد نُسخت بالفعل إلى هذا المسار أو لم توجد بيانات خادم سابقة.
5. أعد النشر.

**تنبيه لحماية بياناتك:** قبل تغيير `DB_PATH`، راجع قيمته الحالية في Render. إذا كان يشير إلى قاعدة بيانات تحتوي على حسابات أو سجلات، فلا تغيّره مباشرة؛ لأن اختيار مسار جديد ينشئ قاعدة فارغة، ولا تنتقل البيانات تلقائيًا. احتفظ بالمسار الحالي أو انسخ ملف قاعدة البيانات القديم إلى القرص الدائم أولًا. ترقية بنية الجداول في `server.js` تحافظ على البيانات الموجودة داخل ملف قاعدة البيانات نفسه.

يُحفظ ملف الجلسات أيضًا داخل مجلد قاعدة البيانات نفسه.

## 4) متغيرات البيئة في Render

أضف أو راجع القيم التالية في Environment:

- `NODE_ENV` = `production`
- `FRONTEND_ORIGIN` = `https://nasab5990-prog.github.io` (النطاق فقط، دون `/athar-ai/`)
- `COOKIE_SAMESITE` = `none`
- `DB_PATH` = `/var/data/athar.sqlite`
- `SESSION_SECRET` = قيمة عشوائية طويلة لا تقل عن 32 حرفًا
- `OTP_SECRET` = قيمة عشوائية مختلفة لا تقل عن 32 حرفًا

لا تضع الأسرار في GitHub أو `config.js` أو داخل ملفات الواجهة.

### وضع الاختبار الحالي

للاختبار دون SMTP:

- `DEMO_LOGIN_ENABLED` = `true`

يظهر نموذج دخول مباشر دون بريد أو رمز تحقق، مع اختيار إحدى شخصيات الاختبار الخمس: المعلم، المعلم الأول، المدير، ولي الأمر، والطالب. عند أول دخول تُنشأ حسابات وبيانات اصطناعية داخل المدرسة المعزولة `DEMO-SCHOOL` فقط. هذا الوضع متاح لكل من يفتح رابط المنصة ما دام مفعّلًا؛ لذلك استخدمه للعرض ببيانات اصطناعية فقط، ولا تضع فيه بيانات طلبة حقيقية أو حسابات مدرسة فعلية. أوقفه بتغيير القيمة إلى `false` عند الانتقال للاستخدام الرسمي.

### التحويل إلى الدخول الرسمي

بعد إعداد بريد SMTP والتحقق من وصول الرسائل:

- غيّر `DEMO_LOGIN_ENABLED` إلى `false`.
- أضف `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM`.

عندها تعرض الواجهة نموذج البريد الرسمي ورمز التحقق لمستخدمي `@moe.om` و`@edu.moe.om` فقط.

## 5) إنشاء أول حساب مدير

يلزم وجود حساب مدير واحد على الأقل قبل إدارة حسابات بقية المدرسة. بعد تشغيل الخادم وتهيئة قاعدة البيانات، أنشئه من Shell الخاص بالخدمة (أو من بيئة تشغيل موثوقة لها وصول إلى ملف قاعدة البيانات):

```bash
node create-user.js manager@moe.om "اسم المدير" principal SCHOOL-001
```

استبدل البريد والاسم ومعرّف المدرسة بالقيم الصحيحة. لا تستخدم بريدًا غير رسمي. بعد ذلك يسجل المدير الدخول برمز OTP عند تشغيل البريد الرسمي، ومن صفحة «الأدوار» ينشئ حسابات المعلمين والمعلم الأول والطلبة وأولياء الأمور. يمكن اختيار طلبة لإسنادهم إلى حساب المعلم؛ أما ولي الأمر فيربط بواحد أو أكثر من الأبناء، والطالب يرتبط بسجل واحد.

حساب الطالب يرتبط بسجل طالب واحد فقط. حساب ولي الأمر يمكن ربطه بأكثر من طالب. أضف سجلات الطلبة قبل إنشاء حسابات الطالب وولي الأمر.

## 6) طريقة الاختبار

1. افتح `https://nasab5990-prog.github.io/athar-ai/`.
2. في وضع الاختبار أدخل رمز الاختبار الخاص الذي خزّنته في Render.
3. أضف طالبًا تجريبيًا، ثم أدخل تقويمًا فرديًا باختيار الطالب.
4. افتح رادار التعثر، وحدد المهارة والطالب، ثم نفّذ التحليل.
5. أنشئ تدخلًا للطالب نفسه، ثم سجّل قياس الأثر قبل/بعد.
6. سجّل الدخول بحساب تجريبي مرتبط بالطالب لاختبار شاشة التقدم، بعد إنشاء الحساب الرسمي وربطه.
7. اختبر أن المعلم لا يرى سجلات معلم آخر، وأن ولي الأمر والطالب لا يريان إلا سجلات الطلاب المرتبطين بحساباتهم.

يمكن فحص الخادم عبر:

- `https://athar-ai-i7he.onrender.com/api/health`
- `https://athar-ai-i7he.onrender.com/api/auth/mode`

ومن المتوقع أن يعيد `/api/records` خطأ 401 عند فتحه دون جلسة دخول.

## 7) ملاحظات مهمة عن البيانات والتحليل

- الطلبة والتقويمات والتدخلات وقياسات الأثر تُقرأ وتُحفظ على الخادم؛ لم تعد قاعدة البيانات التشغيلية هي `localStorage`. لا تُحذف بيانات `localStorage` القديمة من متصفحك، لكنها لا تُرحّل تلقائيًا؛ صدّر نسخة JSON من الإصدار القديم قبل استبداله، ثم استوردها من لوحة القيادة في الإصدار الجديد.
- إعدادات العرض البسيطة مثل الوضع الداكن قد تبقى محلية في المتصفح.
- يدعم الاستيراد ملفات JSON القديمة التي تحتوي على مصفوفات `students` و`assessments` و`interventions`، وكذلك صيغة `records` الجديدة. راجع البيانات المستوردة قبل استخدامها.
- محرك التحليل الحالي يعتمد على سجل التقويمات، والفجوات بين نتائج المهارات السابقة، وخريطة مهارية أولية محدودة تغطي حاليًا الكسور والفهم القرائي وبعض المهارات المرتبطة بهما. **ليس اتصالًا بنموذج لغوي خارجي أو خدمة توليدية**، ولا يقدم تشخيصًا نهائيًا.
- لا تستخدم بيانات طلبة حقيقية قبل استكمال مراجعة أمنية واختبار الصلاحيات واستقرار القرص الدائم وسياسة الخصوصية المعتمدة لدى المدرسة والوزارة.

## 8) استيراد البيانات القديمة

قبل استبدال `app.js` القديم، صدّر البيانات من النسخة القديمة بصيغة JSON، واحتفظ بنسخة آمنة من الملف. بعد تشغيل الإصدار الثالث وتسجيل الدخول، استخدم زر «استيراد» في لوحة القيادة. تُرسل السجلات إلى الخادم على دفعات، وتُرفض السجلات المرتبطة بطالب غير موجود أو غير مسموح به في المدرسة. لا تحذف النسخة الاحتياطية حتى تتأكد من اكتمال الاستيراد ومراجعة السجلات.

## 9) ملاحظة عن ملفات الواجهة المتزامنة

إذا ظهر إصدار قديم بعد النشر، افتح الموقع في نافذة خاصة أو امسح Cache المتصفح، وتأكد من نجاح نشر GitHub Pages بعد استبدال الملفات. يجب أن يكون `index.html` و`app.js` و`config.js` في جذر المستودع نفسه.
