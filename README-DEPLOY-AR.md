# أثَر | دليل التشغيل والاختبار

هذا الدليل يخص النسخة الحالية من منصة أثَر، وليس إصدارات SQLite القديمة.

## 1. بنية النشر الحالية

- **الواجهة:** GitHub Pages من الفرع `main` والمجلد الجذر.
- **رابط الواجهة:** `https://nasab5990-prog.github.io/athar-ai/`
- **ملف ربط الواجهة بالخادم:** `config.js`
- **الخادم:** Render service باسم `athar-ai-postgres-test`.
- **فرع الخادم:** `postgres-migration-test`.
- **رابط API:** `https://athar-ai-postgres-test.onrender.com`
- **أمر البناء:** `npm install`
- **أمر التشغيل:** `node server.js`
- **قاعدة البيانات:** PostgreSQL عبر متغير البيئة `DATABASE_URL`، وليست SQLite.

لا تغيّر رابط API أو فرع خدمة Render أو قاعدة البيانات قبل التأكد من النسخة التي تستخدمها الواجهة. لا تستخدم خدمة Render القديمة `athar-ai-i7he` لهذا الإصدار.

## 2. متغيرات البيئة

تُدار القيم السرية في Render Environment فقط، ولا تُحفظ في GitHub أو ملفات الواجهة.

المتغيرات الأساسية:

- `NODE_ENV=production`
- `DATABASE_URL`: اتصال PostgreSQL الفعلي الذي يستخدمه الخادم.
- `FRONTEND_ORIGIN=https://nasab5990-prog.github.io`
- `COOKIE_SAMESITE=none`
- `SESSION_SECRET`: قيمة عشوائية طويلة لا تقل عن 32 حرفًا.
- `OTP_SECRET`: قيمة عشوائية مختلفة لا تقل عن 32 حرفًا.
- `DEMO_LOGIN_ENABLED=true` للاختبار فقط، ثم `false` قبل الاستخدام الرسمي.

إذا فُعّل الدخول الرسمي، يلزم إعداد SMTP:

- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_SECURE`
- `SMTP_USER`
- `SMTP_PASS`
- `MAIL_FROM`

الدخول الرسمي مقيد بنطاقي `@moe.om` و`@edu.moe.om`.

### الذكاء الاصطناعي

يمكن ضبط مزود واحد:

- `AI_PROVIDER=groq` مع `GROQ_API_KEY` و`GROQ_MODEL` عند الحاجة.
- أو `AI_PROVIDER=openai` مع `OPENAI_API_KEY` و`OPENAI_MODEL` عند الحاجة.

المساعد يقدم مسودات يراجعها المعلم. لا تضع أسماء الطلبة أو أرقامهم أو بياناتهم الشخصية داخل الملاحظات المرسلة إلى مزود خارجي. لا تستخدم بيانات حقيقية قبل اعتماد سياسة الخصوصية والموافقة المؤسسية المناسبة.

## 3. قاعدة البيانات

يستخدم الخادم PostgreSQL، ويهيئ عند التشغيل جداول ربط الحسابات وإعداد الصفوف والشعب والتكليفات الدراسية، مع مراعاة اختلاف نوع أعمدة رمز التحقق بين قواعد البيانات القديمة والجديدة.

أوامر الفحص المتاحة في بيئة تشغيل موثوقة مرتبطة بقاعدة `DATABASE_URL`:

```bash
npm run db:setup
npm run db:verify
npm run check
npm run test:postgres
```

- `db:setup` يطبق ملف `postgres-schema.sql`.
- `db:verify` يتحقق من الجداول والأعمدة والفهارس المطلوبة.
- `check` يفحص صياغة ملفات JavaScript.
- `test:postgres` يجري اختبارًا تكامليًا على بيئة اختبار PostgreSQL، وينشئ سجلات اختبار ثم يحذف السجلات التي أنشأها.

**حماية البيانات:** لا تغيّر `DATABASE_URL`، ولا تحذف قاعدة أو تنقلها، قبل أخذ نسخة احتياطية والتحقق من قاعدة البيانات التي يستخدمها الخادم فعليًا. قد توجد موارد PostgreSQL تجريبية إضافية في حساب الاستضافة؛ لا تفترض أنها قاعدة التشغيل. افحص مضيف `DATABASE_URL` في لوحة Render دون مشاركة كلمة المرور أو رابط الاتصال الكامل.

## 4. بيئة الاختبار

عند تفعيل `DEMO_LOGIN_ENABLED=true` تظهر شخصيات الاختبار الخمس:

- المعلم
- المعلم الأول
- المدير
- ولي الأمر
- الطالب

تُنشأ البيانات الاصطناعية في مدرسة منفصلة باسم `DEMO-SCHOOL`، ولا تُستخدم لتمثيل نتائج ميدانية حقيقية. يتضمن المعلم التجريبي تكليفات للصف الخامس في تقنية المعلومات واللغة العربية، مع طالب وسجلات تقويم وتدخل وقياس أثر توضيحية.

لا تدخل بيانات طلبة حقيقية في بيئة الاختبار. أوقف وضع الاختبار قبل الانتقال إلى الاستخدام الرسمي.

## 5. صلاحيات الأدوار الحالية

- **المعلم:** يعمل ضمن الطلبة والسجلات المتاحة له وفق التكليفات والروابط المعتمدة.
- **المعلم الأول:** يستطيع الاطلاع على سجلات المدرسة وتحليلها ومتابعة المؤشرات، ولا يملك إدارة حسابات المدرسة.
- **المدير:** يدير إعداد الصفوف والشعب والحسابات والتكليفات، ويطّلع على تقارير المدرسة.
- **المشرف التربوي:** دور مستقل للقراءة والتقارير فقط، ويشاهد المدارس المرتبطة بحسابه في جدول `supervisor_schools`. لا يستطيع إنشاء أو تعديل أو حذف السجلات، ولا إدارة حسابات المدارس.
- **ولي الأمر والطالب:** عرض فقط للسجلات المرتبطة بالحساب.

يُنشأ حساب المشرف ويُربط بالمدارس من مسؤول النظام، وليس من مدير مدرسة منفردة. مثال إنشاء حساب لمشرف يتابع مدرستين:

```bash
npm run create-user -- supervisor@edu.moe.om "اسم المشرف" supervisor SCHOOL-001 SCHOOL-002
```

تُستخدم معرّفات المدارس الفعلية بدل القيم التوضيحية. تظهر أسماء المدارس من معرّفاتها حتى تُحدّث أسماء العرض في جدول `supervisor_schools`.

## 6. المناهج

تُعرض قوائم المواد للصفوف المتاحة، لكن الفهرس التفصيلي الموثق للوحدات والدروس ونواتج التعلم لا يغطي جميع الصفوف والمواد بعد. توجد حاليًا بيانات تفصيلية لثلاثة مسارات: رياضيات الصف الأول، وتقنية المعلومات للصف الخامس، وتقنية المعلومات للصف السابع.

لا تعرض المنصة ناتج تعلم على أنه رسمي إذا لم يكن موثقًا من مصدر المنهج. يجب توسيع الفهرس من الكتب والأدلة الرسمية قبل الادعاء بتغطية الصفوف 1–12 وجميع المواد.

## 7. اختبار رحلة العمل

1. سجّل الدخول بشخصية المعلم التجريبي.
2. تحقق من ظهور الصف الخامس والمادتين المسندتين.
3. افتح قائمة الطلبة وتأكد من ظهور الطالب التجريبي في الشعبة 1.
4. أدخل تقويمًا تشخيصيًا واحفظه.
5. افتح رادار التعثر وتأكد من ارتباط التحليل بسجل التقويم.
6. راجع الملاحظة الصفية، ثم أنشئ تدخلًا محددًا للمهارة.
7. احفظ التدخل، ثم سجّل قياس أثر مرتبطًا برقم التدخل نفسه.
8. افتح حساب ولي الأمر والطالب وتأكد من ظهور بيانات الطالب المرتبط فقط.
9. افتح حساب المعلم الأول والمدير وتحقق من اختلاف الصلاحيات.
10. اختبر رفض الوصول غير المصرح به، وعدم ظهور بيانات مدرسة أخرى.

## 8. جاهزية المسابقة

يتوافق مسار أثَر مع محور تحليل نتائج الطلبة وتصميم الخطط العلاجية الفردية، ومع أدوات متابعة التقدم وقياس فاعلية التدخل. قبل التسليم النهائي يلزم توثيق تجربة ميدانية حقيقية، والتحقق من دقة مخرجات الذكاء الاصطناعي، واستكمال سياسة الخصوصية، وتوسيع بيانات المنهج أو تحديد نطاق تجريبي واضح.

يتطلب ملف المشاركة تجهيز تقرير/ملخص علمي باللغة العربية، ورابط التطبيق أو ملفه، وفيديو شارح لا يتجاوز ثلاث دقائق، مع توضيح المشكلة وآلية العمل وتوظيف الذكاء الاصطناعي وقابلية التطبيق الميداني.
